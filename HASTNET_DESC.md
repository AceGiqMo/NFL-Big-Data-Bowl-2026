# Предлагаемая модель: HAST-Net (Horizon-Anchored Spatio-Temporal Network)

## Отправная точка и логика смешения

За основу берётся **наша реализация 5th-place решения**: её факторизованный
spatio-temporal энкодер (SqueezeFormer по времени + spatial-Transformer по
игрокам с distance-bias) уже проверен энд-ту-энд (test RMSE 0.80 против 4.25 у
constant-velocity) и корректно работает с переменными S, P и масками.

Из **1st-place** берём три вещи, которые, судя по их отчёту, дают основной
прирост (val CV-RMSE 0.454): (а) вероятностную голову (μ, σ²) с Gaussian NLL,
(б) аугментации поля (поворот, вертикальный flip, сдвиги x/y) и temporal frame
shift, (в) идею вспомогательных motion-голов (velocity/acceleration).

Из **3rd-place** берём: (а) multi-aux loss с **endpoint-надзором** (их aux
endpoint head), (б) идею отдельного player-interaction пути (глобальный
контекст плейа), (в) time-decayed взвешивание локальной дельта-потери и
глобальную агрегацию RMSE.

Ключевая собственная модификация, мотивированная нашим EDA и нашей кривой
ошибок, — **anchor-residual параметризация траектории с coarse-to-fine
декодированием через контрольные точки**, которая устраняет главный выявленный
дефект всех трёх решений: накопление ошибки (cumsum-дрейф) на длинных горизонтах.

```
Входы (на плей): пре-пас треки (P≤14 игроков × S≤80 кадров @10Hz),
                 статика (role, side, ball_land), горизонт T ∈ [5, 94]
   │
   ▼ [A] Feature stem (из 5th): dx,dy,s,a,sin/cos(dir),sin/cos(o),time-decay
   │        MLP → (B,P,S,D)
   ▼ [B] Факторизованный ST-энкодер ×4 (из 5th):
   │        SqueezeFormer по S  →  spatial-Transformer по P + distance-bias
   │        НОВОЕ: per-play global token g (attention-pooling по P на каждом кадре)
   │        проходит temporal-энкодер вместе с игроками → контекст плейа
   │
   │  gather последнего ВАЛИДНОГО кадра (S_i−1) → release-snapshot
   ▼ [C] Release-mixer (из 5th): ⊕ static ⊕ role-embedding ⊕ role-endpoint-prior
   │        2× Transformer по P + distance-bias → player-токены z_p и контекст g
   │
   ▼ [D] Anchor head (НОВОЕ, развитие aux-endpoint из 3rd):
   │        endpoint ê_p (aux-надзор) + schedule-параметры (τ_p, w_p)
   │        anchor_p(t) = lerp( last_p , ê_p , s_p(t) ),  s_p = sigmoid((t/T − τ_p)/w_p)
   │
   ▼ [E] Control-point decoder (НОВОЕ): M=8 запросов на долях t_m/T
   │        (Fourier-эмбединг доли + RoPE), cross-attention к {z_p, g},
   │        BiGRU по m (дешёвая temporal-согласованность), грубые остатки r_{p,m}
   │
   ▼ [F] Continuous refine (НОВОЕ): для каждого целевого кадра t:
   │        линейная интерполяция r_{p,m} на t  ⊕  MLP( interp, horizon-emb(t,T), z_p )
   │        → остаток ρ_p(t)   (работает при любом T без паддинга до 94)
   │
   ▼ [G] Головы:  pos_p(t) = anchor_p(t) + ρ_p(t)            (main, абсолют)
   │        aux Δ:  следующий кадр (time-decay Huber, из 3rd/1st)
   │        aux σ_p(t): Gaussian NLL (опционально, из 1st)
   └─ Loss = λ_pos·Huber(pos) + λ_end·Huber(ê) + λ_Δ·Σ decay(t)·Huber(Δ) [+ λ_nll·NLL]
```

## Постатейное описание компонентов

**[A] Feature stem (без изменений из 5th).** Покадровые кинематические признаки
(дельты, скорость, ускорение, sin/cos циклических dir/o — факт EDA №8,
time-decay рекентности) проецируются в D=128. Координаты нормализованы флипом
`play_direction` (факт EDA №9: right/left ≈ 53/47).

**[B] Энкодер (5th + глобальный токен).** Факторизация O(P·S² + S·P²) сохранена —
она проверена и дёшева при P≤14 (факт EDA №2). Добавлен один learnable
per-play токен, который на каждом кадре attention-pool'ит игроков и проходит
temporal-энкодер вместе с ними: к моменту релиза модель имеет сжатый контекст
всего плейа g. Это ответ на факт EDA №4 («взаимодействия важны») и на наш
результат «защитники — худшая страта» (DC 0.30 vs TR 0.19): защитник реагирует
не на свою историю, а на состояние плейа в целом.

**[C] Release-mixer (5th + role-embedding).** Snapshot последнего валидного кадра
(gather, а не `[:, -1]` — фикс переменных S) конкатенируется со статикой
(дистанции до ball_land — факт EDA №5) и **learned role-embedding** (вместо
бинарных флагов: факт EDA №6 — роли имеют разные паттерны и разные распределения
дистанции до приземления). Два Transformer по игрокам с distance-bias дают z_p.

**[D] Anchor head (главная новизна).** Модель предсказывает (а) точку конца
траектории ê_p (supervised) и (б) пер-игроковые параметры расписания (τ_p, w_p),
задающие сигмоидный прогресс движения от release-позиции к ê_p. Anchor — это
«грубая баллистика с насыщением», индивидуальная для каждого игрока: ресивер
получает почти монотонный путь к ê_p ≈ ball_land, защитник — путь к точке
перехвата. Все три базовых решения предсказывают либо чистые дельты
(5th, 1st), либо дельты + отдельный endpoint-aux (3rd); ни одно не использует
endpoint как **несущую траекторию**, поэтому ошибка у них накапливается
(cumsum у 5th: наша кривая 0.2→3.7 ярда к o=30; у 1st per-frame RMSE тоже
растёт до multi-yard на конце горизонта).

**[E] Control-point decoder.** Вместо повторения snapshot'а по всем O кадрам и
RNN по всей длине (5th) или паддинга до 48/64 (1st/3rd) декодируем M=8
контрольных точек на нормированных долях горизонта. Память и сложность не
зависят от T (важно: факт EDA №3 — T до 94 кадров, правый хвост; паддинг до 94
в 4 раза дороже текущей схемы). BiGRU по 8 точкам даёт глобальную temporal-
согласованность (наследие RNN-идеи 5th, но на короткой последовательности).

**[F] Continuous refine.** Для каждого целевого кадра t остаток получается
линейной интерполяцией контрольных точек плюс поправка MLP от
(horizon-эмбединг(t, T), z_p). Горизонт-эмбединг = Fourier + RoPE (из 5th),
поэтому одна голова обслуживает любой T, а локальная поправка сохраняет
резкость траектории (факт EDA: траектории не прямые — изломы после приёма).

**[G] Головы и потеря.** Main — абсолютная позиция как anchor + остаток:
ошибка НЕ интегрируется, дрейф устранён конструктивно. Aux Δ (дельта
следующего кадра) с экспоненциальным затуханием по t (из 3rd) держит локальную
гладкость и ранние кадры. Опциональная σ-голова с Gaussian NLL (из 1st) даёт
калиброванную неопределённость и подавляет влияние тяжёлого хвоста (наш факт:
p99 ≈ 3.6 ярда) на основную голову. Маскирование потери по
`player_to_predict` и валидным кадрам сохранено из 5th.

## Отличия от существующих решений (сводная таблица)

| Аспект | 1st place | 3rd place | 5th place (наша база) | HAST-Net (предложение) |
|---|---|---|---|---|
| Параметризация цели | per-frame displacements, Gaussian NLL | Δ от последней точки + aux endpoint + full-temporal | чистые Δ + cumsum | **anchor(endpoint+schedule) + остаток → абсолют, без cumsum-дрейфа** |
| Горизонт T | фикс. паддинг 48 | фикс. 64 + срез батча | repeat snapshot + RoPE + BiLSTM/BiGRU по O | **M=8 контрольных точек + continuous refine: любой T≤94 без паддинга** |
| Взаимодействия игроков | отдельный interaction-path (13→64, 2×Trans, sum/mean) | spatial-attention внутри STEncoder | spatial-attention по кадрам + distance-bias | как в 5th **+ per-play global token g** (контекст для защитников) |
| Информация о роли | признаки | порядок слотов по дистанции до пасующего | бинарные флаги | **learned role-embedding + role-conditioned endpoint prior** |
| Головы | μ, σ², aux μ/σ² (vel/accel) | main + next-frame + endpoint + full-temporal | одна Δ-голова | main pos + endpoint + next-frame Δ + опц. σ (NLL) |
| Потеря | Gaussian NLL + vel/accel aux | time-decayed Huber + aux | masked Huber по Δ | **λ_pos·Huber(pos) + λ_end·Huber(ê) + λ_Δ·decay-Huber(Δ) (+NLL)** |
| Аугментации | rot/flip/shift + frame shift | нет (в репродукции) | нет | **rot/flip/shift + frame shift (из 1st), согласованно с флипом поля** |
| Энкодер | conv-stem + res-blocks + Trans×3 | 2× STEncoder (temp+spatial) | 4× SqueezeFormer + spatial Trans | энкодер 5th (проверен) + global token |
| Декодер | conv-proj → 48 кадров + ResBlocks | Trans-encoder → головы | RNN∥ + 2× ST-blocks | control-point decoder (BiGRU по 8) + MLP-refine |
| Неопределённость | да (NLL) | нет | нет | опциональная σ-голова |
| Контроль дрейфа | нет | частично (endpoint aux) | нет | **явный anchor** |

Обоснование через EDA и наши метрики:
- T ∈ [5, 94], правый хвост (медиана 10) → control-points + refine вместо
  паддинга до 94 (память) и вместо RNN по всей длине (стоимость).
- Наша кривая RMSE(o): 0.2 → 3.7 к o=30 при 1.0 → 15.4 у baseline → anchor
  убирает интегрирование локальной ошибки.
- DC-защитники — худшая страта (медианы 0.30 vs 0.19) → global token g и
  role-endpoint prior дают защитнику контекст плейа, а не только свою историю.
- Тяжёлый хвост ошибок (p90 1.6, p99 3.6) → Huber + опц. NLL вместо MSE/NLL-only.
- Циклические dir/o → sin/cos сохранены; слабые парные корреляции → не
  пруним признаки, оставляем полную секвенс-модель.
- Цели — подмножество игроков (TR всегда, DC частично) → masked loss и
  per-role метрики сохранены; утечки исключены week-split'ом (GroupKFold —
  только как опциональная проверка робастности, идея 1st).
## Режим обучения и план оценки (без изменения harness)

- Оптимизатор: AdamW (2D-веса — опционально Muon, ablation), EMA 0.995,
  cosine + warmup 500 шагов, grad-clip 1.0, early stopping patience 6 по val RMSE.
- Агрегация RMSE — глобальная (сумма квадратов / суммарное число валидных
  координат), как рекомендовано в репродукции 3rd; доверительные интервалы —
  block-bootstrap по плейам (block=8, 1000 ресемплов), тот же harness, что и у
  нашего 5th-прогона (test = week 18, 750 плейов) → числа сравнимы напрямую.
- Базовый набор λ: λ_pos=1.0, λ_end=0.5, λ_Δ=0.5 (decay exp(−0.03·t)), λ_nll=0.1
  (ablation: 0).
- План ablations (закрывает пункт «model improvements» и даёт таблицу в репорт):
  (A) anchor on/off (сравнение с чистой Δ-параметризацией 5th);
  (B) global token on/off; (C) aux-потери on/off; (D) аугментации on/off;
  (E) NLL on/off; (F) M ∈ {4, 8, 16} контрольных точек.
- Ожидаемый эффект (гипотезы для репорта): RMSE(o=30) ↓ с ≈3.7 до <2.5 ярда;
  страта DC ↓ сильнее, чем TR (за счёт g и endpoint prior); общий test RMSE
  ↓ с 0.80 до ≈0.6–0.7 при сохранении медианы ≈0.2–0.3 ярда; калибровка σ
  согласуется с эмпирическими перцентилями (p90/p99).
- Риски и меры: (а) anchor может «задавить» локальные изломы → компенсируется
  Δ-aux и MLP-refine; (б) schedule-параметры могут вырождаться → ограничены
  sigmoid-диапазоном и supervised endpoint; (в) рост памяти от cross-attention
  к g незначителен (M=8 запросов против O=94 кадров в схеме 5th).
